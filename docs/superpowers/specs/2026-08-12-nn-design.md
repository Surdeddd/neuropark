# nn — каталог парка нейронок и единый контракт вызова

**Дата:** 2026-08-12
**Статус:** дизайн одобрен, спека на вычитке
**Заменяет:** `ultra` и `ultra-fleet` (репозитории удалены с GitHub 2026-08-12, локальные копии остались в `~/Projects/Personal/{ultra,ultra-fleet}`)

## 1. Зачем

У пользователя парк нейронок разъехался по трём машинам и десятку рантаймов: пять agent-CLI, whisper в трёх разных папках, MLX-модели, ComfyUI на winpc с 282 воркфлоу, облачные генераторы, локальный TTS, эмбеддер. Знание «чем это сделать, где оно лежит, какими флагами звать» живёт в голове и в CLAUDE.md, а не в исполняемом виде. Каждая новая цепочка (транскрипт → перевод → озвучка → сборка) собирается руками заново.

`nn` решает две задачи:

1. **Анализ парка** — единый реестр всех нейронок на всех машинах: что есть, где, живое ли, чем отличается от соседа по capability.
2. **Быстрая интеграция** — единый контракт вызова, при котором выход одной нейронки годится входом другой без ручной подгонки.

### Почему не продолжаем ultra

`ultra` за месяц собрал 4 вызова, досье моделей ни разу не заполнились. Причины: требовал ручного посева конфигов и досье; нёс сложность (квотные окна, worktree, оркестрация), польза которой не наступала раньше, чем кончалось терпение; сам себя не звал, потому что в описании не было явных триггеров.

Полный набор фич сохраняется по прямому решению пользователя, но с двумя обязательными поправками, снимающими причину смерти:

- **Всё самозаполняющееся.** Досье пишутся автоматически из логов запусков, квоты пересчитываются из тех же логов. Ручной посев не требуется нигде, кроме `nn adapt` (один раз) и правки манифестов при добавлении нейронки.
- **Фазовая поставка с проверкой.** Шесть фаз, каждая проверяется отдельно и полезна сама по себе. Ядро полезно без оркестрации; оркестрация не блокирует ядро.

## 2. Границы

**В охвате:** все нейронки на всех устройствах пользователя — текстовые agent-CLI, локальные модели (MLX, whisper.cpp, ollama/LM Studio если появятся), ComfyUI-семейство на winpc, облачные генераторы по API-ключу, вспомогательный медиа-клей (ffmpeg) как участник цепочек.

**Вне охвата (осознанно):**

- не менеджер загрузки моделей — качают существующие скрипты (`~/scripts/winpc/*`, aria2 по SSH)
- не MCP-сервер (может появиться позже поверх CLI, схему это не меняет)
- не GUI
- не замена плагинов `codex`/`grok`/`kimi`/`g-cc` для интерактивного rescue: они остаются для разговорных обращений, `nn orchestrate` — для программного маршрута с учётом квот и досье
- не редактор ComfyUI-воркфлоу (правило «граф не редизайнить» остаётся в силе)

## 3. Принципы

1. **Универсальность через данные, не через код.** В движке нет списка capability, нет списка машин, нет списка нейронок. Всё это файлы. Добавление нейронки — один файл манифеста; добавление машины — один файл хоста; новый сценарий — один файл рецепта.
2. **Ноль абсолютных путей пользователя в данных.** Только `~`, переменные окружения, `which`, и `paths` конкретного хоста. Тот же плагин на чужой машине даёт другой результат скана и работает.
3. **Только stdlib python 3.11+.** Без jq, без bash-измов в движке, чтобы жил на macOS, Linux и Windows. Шаблоны команд провайдеров могут быть шелловыми и иметь per-os варианты.
4. **Никаких молчаливых подмен модели.** Провайдер недоступен или окно квоты исчерпано — движок отказывается и называет альтернативу. Переключение только по явному `--fallback` или объявленному в рецепте `on_quota`.
5. **Ничего не применяется само.** Патчи из worktree не мержатся, remote-команды на хостах с `auto: false` печатаются, а не исполняются, `nn burn` без `--yes` только предлагает.
6. **Детерминированный рантайм.** LLM участвует только внутри провайдеров и один раз в `nn adapt`. Резолв, маршрутизация, учёт квот — обычный код, отлаживаемый глазами.

## 4. Архитектура

Четыре слоя.

```
данные (в репо, git)        стейт (~/.claude/nn/)          движок (python)             поверхности
─────────────────────       ────────────────────────       ───────────────────         ─────────────
providers/*.json            registry.<hostname>.json       scan.py                     CLI `nn`
hosts/*.json                runs.jsonl                     resolve.py                  плагин Клода:
capabilities.json           quota.json                     transport/{local,manual,      skills/nn/SKILL.md
bridges/*.json              dossiers/<provider>.md                   ssh,http}.py       commands/nn.md
recipes/*.json              out/<run-id>.{log,txt,...}     bridge.py
roles.json                  worktrees/<run-id>/            recipe.py
dossier-rules.json          burn-queue.jsonl               quota.py
                            state.json (watermarks)        dossier.py
                                                           orchestrate.py
                                                           worktree.py
                                                           schedule.py
                                                           registry.py, render.py, cli.py
```

Каждый модуль движка — отдельный файл с одной ответственностью, ориентир 80–200 строк. Итого ориентировочно 1200–1500 строк движка плюс ~50 манифестов-приоров.

## 5. Схемы данных

### 5.1 Провайдер — `providers/<id>.json`

```json
{
  "id": "whisper-cpp-large-v3",
  "capability": "transcribe",
  "kind": "model",
  "host": "local",
  "rank": 10,
  "detect": {
    "bin": "whisper-cli",
    "files": ["~/Models/whisper/ggml-large-v3.bin"]
  },
  "version_cmd": "whisper-cli --version",
  "vars": { "model": "~/Models/whisper/ggml-large-v3.bin" },
  "io": { "in": ["video", "audio"], "out": "srt" },
  "pre": "ffmpeg -nostdin -i {in} -ar 16000 -ac 1 -y {tmp}.wav",
  "run": "whisper-cli -m {model} -f {tmp}.wav -osrt -of {out_base} -l auto",
  "timeout_s": 1800,
  "notes": "точнее turbo примерно вдвое медленнее; вход обязан быть 16k mono, это делает pre"
}
```

Поля:

| поле | обяз. | смысл |
|---|---|---|
| `id` | да | уникальный kebab-case, совпадает с именем файла |
| `capability` | да | одна строка. Одна нейронка с двумя capability = два манифеста |
| `kind` | да | `model` \| `tool` \| `agent`. `tool` (ffmpeg) участвует в цепочках, но не считается нейронкой в `nn ls --models` |
| `host` | нет | id хоста, по умолчанию `local` |
| `rank` | нет | целое, по умолчанию 0; больше — приоритетнее среди доступных |
| `detect` | да | см. 5.2 |
| `version_cmd` | нет | команда, чей первый вывод пишется в реестр как версия |
| `vars` | нет | подстановки для шаблонов; значения проходят раскрытие `~` и env |
| `io.in` | да | список типов-классов, которые принимает |
| `io.out` | да | один тип-класс на выходе |
| `io.out_ext` | нет | расширение, которым провайдер реально пишет файл, если это не первое расширение класса. Добавлено 2026-08-12 по факту интеграции: `ben-voice.py` всегда кодирует OGG/Opus, и передача ему `.wav` ломала внутреннюю конвертацию ffmpeg |
| `pre` / `run` / `post` | `run` да, если нет `adapter` | шаблоны команд; допускаются per-os ключи `run.darwin`, `run.linux`, `run.win` |
| `adapter` | нет | путь к скрипту-обёртке относительно корня плагина; взаимоисключающе с `run` |
| `timeout_s` | нет | по умолчанию 900 |
| `window_h`, `soft_cap_calls` | нет | параметры квотного окна (фаза 3) |
| `quota_patterns` | нет | список регулярок по stderr, распознающих исчерпание квоты |
| `requires_key` | нет | список env-переменных; их отсутствие даёт статус `needs-key` |
| `roles` | нет | подсказки для `nn adapt` |
| `notes` | да | человеческий текст: скорость, качество, известные грабли |

Переменные шаблонов: `{in}`, `{out}`, `{out_base}` (без расширения), `{tmp}` (уникальный префикс в temp), `{dir}` (рабочая директория), `{prompt_file}` (файл с промптом для текстовых провайдеров), `{host.paths.<key>}`, плюс любые ключи из `vars`. Неизвестная переменная в шаблоне — ошибка валидации, код выхода 7, а не пустая подстановка.

### 5.2 Стратегии detect

Все ключи внутри `detect` соединяются логическим И. Пустой `detect` запрещён.

| ключ | проверка |
|---|---|
| `bin` | бинарь находится в PATH либо в списке известных мест (`~/.local/bin`, `/opt/homebrew/bin`, `~/.grok/bin`, `~/.kimi-code/bin`) |
| `files` | все пути существуют после раскрытия `~`/env |
| `glob` | шаблон даёт хотя бы одно совпадение (папки моделей) |
| `env` | переменные окружения непусты |
| `http` | GET/HEAD на URL отвечает за 3 секунды |
| `python` | модуль импортируется указанным интерпретатором |
| `npm` | пакет виден `npm ls -g --depth=0` |
| `docker` | образ есть в `docker images` |
| `brew` | формула установлена |

Различие статусов принципиально: не найден бинарь — `missing`; бинарь есть, но нет ключа из `requires_key` — `needs-key`; хост недостижим — `stale` с сохранением прошлых данных и даты `last_seen`.

### 5.3 Хост — `hosts/<id>.json`

```json
{
  "id": "winpc",
  "kind": "ssh",
  "addr": "winpc-cc",
  "os": "windows",
  "auto": false,
  "probe": "ssh -o ConnectTimeout=3 -o BatchMode=yes winpc-cc true",
  "paths": { "models": "D:/models", "comfy": "http://127.0.0.1:8188" },
  "env": {},
  "notes": "умеет засыпать посреди джоба; сеть I226 EEE флапает"
}
```

`kind`: `local` (исполняем прямо) · `ssh` (через ssh) · `http` (POST на эндпоинт) · `manual` (только печатаем команду). `auto: false` на любом хосте переводит его в поведение `manual` независимо от `kind` — это дефолт для `winpc` и `mac-mini` в первой версии.

`env` хоста инжектится в окружение запуска. Здесь же кодируется правило биллинга: у `mac-mini` в `env` живут `ANTHROPIC_BASE_URL` и указание брать ключ из `~/.config/maxim-secrets/`, у `macbook` (`local`) `env` пустой — подписка Max не должна видеть API-ключ. Значения-секреты не хранятся в файле хоста: допускается только форма `{"ANTHROPIC_API_KEY": "@file:~/.config/maxim-secrets/ethereal.key"}`, движок читает файл в момент запуска.

### 5.4 Capability и типы — `capabilities.json`

```json
{
  "types": {
    "video": ["mp4", "mov", "mkv", "webm"],
    "audio": ["wav", "mp3", "m4a", "ogg", "flac"],
    "image": ["png", "jpg", "jpeg", "webp"],
    "text":  ["txt", "md"],
    "srt":   ["srt", "vtt"],
    "json":  ["json"],
    "mesh":  ["glb", "gltf", "obj", "fbx"],
    "vector":["npy"]
  },
  "capabilities": {
    "transcribe":    { "in": ["video", "audio"], "out": "srt" },
    "tts":           { "in": ["text"],           "out": "audio" },
    "image":         { "in": ["text"],           "out": "image" },
    "image-edit":    { "in": ["image"],          "out": "image" },
    "video-gen":     { "in": ["text", "image"],  "out": "video" },
    "music":         { "in": ["text"],           "out": "audio" },
    "mesh":          { "in": ["image", "text"],  "out": "mesh" },
    "embed":         { "in": ["text"],           "out": "json" },
    "text":          { "in": ["text"],           "out": "text" },
    "translate":     { "in": ["text", "srt"],    "out": "same" },
    "audio-clean":   { "in": ["audio"],          "out": "audio" },
    "subtitle-burn": { "in": ["video"],          "out": "video", "extra": ["srt"] },
    "compose":       { "in": ["video"],          "out": "video", "extra": ["audio"] }
  }
}
```

Файл — данные, а не enum в коде. Манифест с capability, отсутствующим в файле, работает; `nn doctor` выдаёт предупреждение и предлагает дописать запись, чтобы стыковка типов знала про него.

Два особых значения:

- `"out": "same"` — capability сохраняет тип входа (перевод srt даёт srt, перевод txt даёт txt). Резолвер и стыковка типов трактуют выход как фактический тип входа.
- `"extra": [...]` — capability требует дополнительных входов помимо основного. В рецепте они подаются через `extra_in`, в CLI — повторным `--extra <файл>`. Отсутствие обязательного дополнительного входа — код 8.

### 5.5 Мостик — `bridges/<id>.json`

```json
{ "id": "video-to-audio", "from": "video", "to": "audio",
  "detect": { "bin": "ffmpeg" },
  "run": "ffmpeg -nostdin -i {in} -vn -ar 16000 -ac 1 -y {out}",
  "out_ext": "wav" }
```

Мостик вставляется автоматически, когда тип входа не входит в `io.in` выбранного провайдера, но существует доступный мостик `входной_тип → любой из io.in`. Цепочка мостиков ограничена одним шагом: два подряд не ищем, это источник неожиданных конвертаций. Нет мостика — код выхода 8.

### 5.6 Рецепт — `recipes/<id>.json`

```json
{
  "id": "bilingual-subs",
  "description": "видео → двуязычные сабы, вжжённые в картинку",
  "steps": [
    { "capability": "transcribe" },
    { "capability": "translate", "vars": { "lang": "ru" } },
    { "capability": "subtitle-burn", "in": "{input}", "extra_in": ["{step1.out}"] }
  ],
  "on_quota": "fail"
}
```

Шаг ссылается либо на `capability`, либо на `role` (тогда провайдер берётся из `roles.json`) — это делает медиа-пайплайны и модельную оркестрацию одним механизмом. Выход шага N по умолчанию становится входом N+1. `on_quota`: `fail` (по умолчанию) либо `fallback`. Опциональный `provider` на шаге пришпиливает конкретного провайдера.

Ссылки на шаги: индексация с нуля в порядке объявления, `{stepK.out}` — выход K-го шага, `{input}` — исходный вход рецепта. В примере выше `subtitle-burn` получает основным входом исходное видео (`{input}`), а сабы — как дополнительный вход через `extra_in`. Ссылка на шаг с индексом не меньше текущего — ошибка валидации, код 7.

### 5.7 Роли — `roles.json`

```json
{
  "roles": {
    "core":      { "providers": ["claude-fable", "claude-opus"], "worktree": false },
    "spec":      { "providers": ["codex", "claude-opus"],        "worktree": false },
    "mechanics": { "providers": ["grok", "codex"],               "worktree": true  },
    "frontend":  { "providers": ["kimi", "codex"],               "worktree": true  },
    "review":    { "providers": ["kimi", "codex", "grok"],       "worktree": false },
    "scout":     { "providers": ["grok"],                        "worktree": false }
  },
  "patterns": {
    "default": ["spec", "work", "cross-review", "verdict"],
    "quick":   ["work", "verdict"]
  }
}
```

Генерируется `nn adapt` один раз, дальше правится руками. Порядок в `providers` — цепочка фолбэков роли.

## 6. Стейт

| файл | содержимое |
|---|---|
| `registry.<hostname>.json` | результат скана: по каждому провайдеру статус (`ok`/`missing`/`needs-key`/`stale`), версия, `last_seen`, причина отказа. Имя с хостнеймом — чтобы синк через Syncthing не затирал соседнюю машину |
| `runs.jsonl` | одна строка на запуск: `ts, run_id, provider, capability, host, in_type, out, exit, outcome, ms, stderr_tail` |
| `quota.json` | производное от `runs.jsonl`: окна, счётчики, `exhausted_until` |
| `dossiers/<provider>.md` | до 40 строк уроков, секции `## observed` и `## instructions` |
| `out/<run-id>.*` | логи и артефакты запуска |
| `worktrees/<run-id>/` | изолированные git-worktree на время работы |
| `burn-queue.jsonl` | отложенные задачи под простаивающую квоту |
| `state.json` | вотермарки: до какой строки `runs.jsonl` дистиллированы досье и пересчитаны квоты |

## 7. Алгоритм резолва

Вход: capability (или роль), тип входного файла, флаги.

1. **Кандидаты.** Манифесты с нужным capability. Для роли — список `providers` роли в объявленном порядке.
2. **Фильтры,** каждый отказ запоминается с причиной для `nn why`:
   - статус в реестре `ok`; `missing`/`needs-key` отпадают
   - хост достижим согласно политике; хост с `auto: false` не отпадает, а помечается «требует ручного запуска»
   - `os` совпадает либо шаблон имеет per-os вариант
   - тип входа принимается напрямую либо есть одношаговый мостик
   - окно квоты не исчерпано (`quota.json`)
3. **Сортировка:** явный `--provider` → пришпиленный в рецепте → `rank` по убыванию → локальный хост раньше удалённого → недавний успех по `runs.jsonl`.
4. **Результат:** выбранный провайдер + список отклонённых с причинами. Пусто → код 2.

`nn why <capability>` печатает ровно эту таблицу — это и есть «анализ парка» в исполняемом виде.

## 8. Исполнение и конверт

Порядок: рендер шаблонов → мостик (если нужен) → `pre` → `run` → `post` → классификация исхода → запись `runs.jsonl` → печать конверта в stdout.

```json
{ "status": "ok", "run_id": "1785900000-whisper-cpp-large-v3",
  "provider": "whisper-cpp-large-v3", "capability": "transcribe", "host": "local",
  "in": "video.mp4", "out": "~/.claude/nn/out/1785900000-....srt",
  "bridge": null, "ms": 41230, "exit": 0, "outcome": "success",
  "log": "~/.claude/nn/out/1785900000-....log", "patch": null }
```

**Классы исхода** (наследуются из ultra, где показали себя): `success` · `empty` (файл отсутствует, нулевой размер, либо для текстового capability меньше 24 непробельных символов — ловит ответы вида «Ready to work. What's the task?») · `timeout` · `quota` (сработал `quota_patterns`) · `refused` · `crash`. `exit 0` не считается доказательством успеха, решает класс.

**Коды выхода CLI:** `0` успех · `2` нет провайдера под capability · `3` требуется ручной запуск, команда напечатана · `4` провайдер упал · `5` реестра нет либо он старше 30 дней · `6` квота исчерпана · `7` невалидный манифест, шаблон или рецепт · `8` тип входа не поддержан и мостика нет либо не хватает обязательного дополнительного входа.

Слово «просрочено» имеет два разных смысла, их не путать: статус провайдера `stale` означает «хост был недостижим в последний скан, данные от прошлого раза сохранены»; просроченный **реестр** — файл целиком старше 30 дней, это код 5 с подсказкой сделать `nn scan`.

**Ретраи:** `timeout` и `crash` повторяются один раз (`--retries N` меняет). `quota`, `refused`, `empty` не повторяются никогда: первые два жгут окно впустую, третий повторит тот же пустой ответ.

## 9. Квоты

Манифест или хост объявляет `window_h` и `soft_cap_calls`. `quota.py` пересчитывает `quota.json` из хвоста `runs.jsonl` от вотермарки: скользящее окно, счётчик вызовов, время начала окна, `exhausted_until` (ставится при исходе `quota` = сейчас + `window_h`).

`nn quota` — таблица: провайдер, окно, сожжено/лимит, когда окно закроется, простаивает ли. `nn burn` находит окна, которые истекут неиспользованными, показывает задачи из `burn-queue.jsonl`, подходящие по capability, и без `--yes` только предлагает.

Резолвер учитывает квоту как предпроверку доступности. Исчерпано у единственного кандидата → код 6 с названием альтернативы, но без автопереключения (принцип 4).

## 10. Досье

Заполняются сами — это ключевое отличие от ultra.

`dossier.py` читает новые строки `runs.jsonl` от вотермарки, группирует по провайдеру и строит уроки **без LLM**, по шаблонам от исхода и подписи stderr:

- три `empty` подряд на одном capability → инструкция «этому провайдеру нужен промпт-файл, инлайн-промпт даёт приветствие»
- `timeout` дважды на одном capability → инструкция «поднять `timeout_s` до удвоенного максимума наблюдённой длительности успешных запусков этого провайдера, минимум 1800»
- одна и та же подпись stderr (первая строка, приведённая к нижнему регистру, с вырезанными числами и путями) встретилась трижды → строка в `observed` с частотой и датой последнего раза; в `instructions` попадает только если подпись совпала с известным шаблоном из `dossier-rules.json` (данные, пополняются вручную по мере накопления грабель)

Формат: `## observed` (факты со счётчиками и датами) и `## instructions` (императивы для подмешивания в промпт). Ограничение 40 строк, вытеснение FIFO по секции `observed`. `nn learn` запускается вручную или автоматически после 20 новых записей в `runs.jsonl`. Флаг `--llm` просит лид-модель переписать секцию `instructions` человечнее — опция, не требование.

Для провайдеров capability `text` досье подмешивается в промпт по умолчанию, отключается `--no-dossier`.

## 11. Worktree

`nn run` и `nn orchestrate` с `--worktree` (или ролью, у которой `worktree: true`):

1. `git worktree add ~/.claude/nn/worktrees/<run-id> HEAD --detach` в целевом репо
2. провайдер работает внутри worktree
3. `git -C <wt> add -A && git -C <wt> diff --cached HEAD > out/<run-id>.patch`
4. пустой патч → исход `empty`, worktree удаляется
5. непустой → патч остаётся артефактом, worktree удаляется, если не передан `--keep-worktree`

Патч никогда не применяется и не коммитится: мерж — решение пользователя. Целевой репо не должен быть в состоянии rebase/merge — иначе отказ с кодом 4 до создания worktree.

## 12. Оркестрация

`nn orchestrate "<задача>" [--dir D] [--pattern default] [--fanout N]`.

Паттерн — список **стадий**, не ролей. Соответствие стадия → роль фиксировано в коде и однозначно: `spec` → роль `spec`; `work` → роль из `--role`, по умолчанию `mechanics` (либо `frontend`, если явно передан); `cross-review` → роль `review` с обязательным исключением вендора, написавшего патч; `verdict` → роль `core`. Неизвестная стадия в паттерне — код 7.

Паттерн `default` — четыре стадии, маршрут детерминированный, LLM только внутри провайдеров:

1. **spec** — роль `spec` превращает формулировку в строгую спеку (файл)
2. **work** — роль `mechanics`/`frontend` работает в worktree, отдаёт патч. При `--fanout N` — N воркеров на одной спеке в отдельных worktree
3. **cross-review** — роль `review`, обязательно **другой вендор**, чем автор патча; при fanout ревьюятся все патчи
4. **verdict** — роль `core` выбирает патч и пишет отчёт: что принять, что переделать, чего не хватает

Итог — отчёт плюс путь к патчу. Ничего не применяется. Каждый вызов идёт через обычный резолвер, значит учитывает квоты, досье и статусы реестра.

## 13. Дрейф парка

**Изменено 2026-08-12 по решению пользователя:** расписаний и телеграм-алёртов НЕТ. Скан запускает человек командой `nn scan`, и там же видит, что изменилось с прошлого раза. Изначально в этом разделе были launchd/systemd/schtasks и уведомления через `notify-maxim.sh` — выпилены целиком, чтобы не было инфраструктуры, которой предстоит сгнить.

`nn scan` сравнивает новый реестр с прошлым и печатает дрейф четырёх видов: провайдер появился, исчез, сменил статус, обновил версию. Первый скан дрейфом не считается — сравнивать не с чем. В `--json` дрейф идёт отдельным полем для агентов.

## 14. Поверхности

**CLI:** `scan` · `ls` · `why` · `run` · `recipe` · `orchestrate` · `quota` · `burn` · `learn` · `adapt` · `doctor` · `stats`.

`nn ls` по умолчанию человеческая таблица; `--json` для агентов. `nn stats` — счётчики вызовов по командам и провайдерам из `runs.jsonl`: прямая профилактика повторения истории ultra, мёртвые фичи видны цифрами.

`nn doctor` проверяет: битые пути в `vars` и `detect.files`, отсутствующие env-ключи, дубли `id`, capability без единого доступного провайдера, манифесты, ни разу не выигравшие резолв, capability вне `capabilities.json`, шаблоны с неизвестными переменными, недостижимые хосты.

**Плагин Клода:** `.claude-plugin/plugin.json` + marketplace-манифест, `commands/nn.md` (слэш `/nn`), `skills/nn/SKILL.md`. В описании скилла — явные триггеры «когда звать» (транскрипт, озвучка, генерация картинки, «чем это сделать», «что у меня есть для X», сборка цепочки), потому что отсутствие таких триггеров было одной из причин, почему ultra не звался. CLI при этом самостоятелен и работает без Клода.

## 15. Тесты

Без сети и без обращения к платным моделям.

**Юниты:** порядок резолва и все фильтры (на фейковых манифестах, где `run` — `printf`/`cp`) · согласование типов и вставка мостика · рендер шаблонов, включая ошибку на неизвестной переменной · классификация исходов, в том числе `empty` по порогу символов · арифметика окон квот на синтетическом `runs.jsonl` · дистилляция досье и вытеснение при переполнении · генерация файлов расписания под три ОС (пишем в tmp, сверяем содержимое) · валидация схем манифестов, хостов, рецептов · разбор `@file:` в `env` хоста · логика worktree на временном git-репо (реальный `git worktree`, без сети).

**Интеграционные на фейковых провайдерах:** цепочка из трёх шагов через `ffmpeg -f lavfi` и `printf`, проверка что выход шага стал входом следующего и что мостик вставился.

**Живые смоуки, помеченные `-m smoke`, офлайн:** транскрипт трёхсекундной синусоиды, сгенерированной ffmpeg; TTS одной фразы через `ben-voice.py`.

**Проверка перед «готово»:** `ruff check`, `mypy --strict` по движку, `pytest`, плюс `nn doctor` на реальной машине без ошибок. Цель — `make check` одной командой.

## 16. Фазы

Каждая фаза заканчивается работающей и проверенной функциональностью.

| фаза | содержимое | критерий приёмки |
|---|---|---|
| 1. Ядро | схемы и валидация, `scan`, `ls`, `why`, `run` (local + manual), `doctor`, реестр, `runs.jsonl`, конверт, коды выхода | `nn scan` находит реальный парк мака; `nn run transcribe <файл>` даёт srt; `nn why` объясняет выбор; юниты и оба смоука зелёные |
| 2. Стыковка | `capabilities.json`, мостики, рецепты, согласование io | рецепт `bilingual-subs` проходит на реальном коротком видео; мостик вставляется автоматически |
| 3. Учёт | `quota.py`, `quota.json`, `nn quota`, квота-осведомлённый резолвер, `nn burn`, `burn-queue.jsonl` | синтетический `runs.jsonl` даёт правильные окна; исчерпание даёт код 6 без подмены |
| 4. Обучение | `dossier.py`, авто-дистилляция, подмешивание в промпт, `nn learn` | после серии искусственных неудач досье заполнилось само и попало в промпт |
| 5. Оркестрация | `roles.json`, `nn adapt`, `nn orchestrate`, worktree и патчи | на живом репо `orchestrate` выдаёт патч + отчёт, рабочее дерево не тронуто, ревью сделал другой вендор |
| 6. Свежесть и упаковка | дрейф в выводе `nn scan`, `nn stats`, плагин-манифест, скилл с триггерами, `commands/nn.md`, `install.sh`, README | скан показывает исчезнувшую нейронку; плагин ставится с нуля на чистом профиле |

Приоры (~50 манифестов) наполняются не разово, а по фазам: фаза 1 — то, что подтверждено на диске мака; фаза 2 — медиа-клей и мостики; фаза 5 — agent-CLI и роли; фаза 6 — облачные и winpc-декларации.

Реализационный план пишется **не на все шесть фаз сразу**: сначала детальный план на фазы 1–2 (они дают работающий продукт), затем по факту прохождения — план на 3–4 и отдельно на 5–6. Причина простая: план на 1500 строк кода вперёд гарантированно разъедется с реальностью после первой же фазы, а спека остаётся общим ориентиром.

## 17. Риски

| риск | смягчение |
|---|---|
| Повторение судьбы ultra: фичи есть, вызовов нет | `nn stats` показывает мёртвые фичи цифрами; договорённость выпиливать нулевые через месяц; триггеры «когда звать» в описании скилла |
| Манифесты разъезжаются с реальностью (модели переехали) | `nn doctor` + дрейф в выводе ручного `nn scan`; статус `stale` вместо тихого исчезновения |
| Универсальность разгоняет объём кода | движок разложен по модулям 80–200 строк, каждый тестируется отдельно; транспорты `ssh`/`http` в первой версии experimental и покрыты фейками |
| Секреты утекают в git | в файлах хостов только форма `@file:`, значения читаются в рантайме; стейт лежит вне репо, в `~/.claude/nn/` |
| Путаница биллинга (подписка против ethereal-ключа) | правило закодировано в `env` хостов: у `local` пусто, у `mac-mini` явные `ANTHROPIC_*` |
| Автоматика применяет что-то сама | патчи не мержатся, `auto: false` печатает команду, `burn` требует `--yes`, скан только читает |

## 18. Решённые развилки

- Имя CLI — `nn` (проверено: свободно). Репо и плагин — `neuropark`. Слэш-команда — `/nn`.
- Одна нейронка с несколькими capability описывается несколькими манифестами, а не списком в одном: так `rank` и `notes` остаются осмысленными для каждой роли отдельно.
- Формат данных — JSON, не YAML/TOML: совпадает с остальной инфраструктурой пользователя, парсится stdlib без зависимостей.
- Цепочка мостиков ограничена одним шагом осознанно.
- Стейт лежит в `~/.claude/nn/`, а не в репо: переживает переустановку плагина, не попадает в git.
- На GitHub не публикуем, пока не пройдут фазы 1–3 на живом использовании.
