# nn — парк нейронок / neural park

Язык вывода переключается `NN_LANG=ru` или `NN_LANG=en`. Output language switches with `NN_LANG`.

`nn` знает всё, что у пользователя есть из нейронок на всех машинах, и умеет их запускать по единому контракту. Бинарь — `bin/nn` в корне плагина (или `nn`, если он в PATH).

## Когда звать, а когда нет

**Звать:**
- спрашивают «чем сделать X» или «что у меня есть для X» → `nn ls X` и `nn why X`
- нужна медиа-операция из списка capability → `nn run <capability> <файл>`
- нужна цепочка (транскрипт → перевод → сабы) → `nn recipe run`
- задачу стоит прогнать через несколько моделей с ревью → `nn orchestrate`
- спрашивают про остаток квоты подписок → `nn quota`

**Не звать:** для разговорного обращения к одной модели (для этого есть плагины `codex`/`grok`/`kimi`), для правки ComfyUI-воркфлоу, для скачивания моделей.

## Первое, что делать в новой сессии

Реестр парка может быть просрочен. Если любая команда вернула код 5 — сделай `nn scan` (он же покажет, что изменилось с прошлого раза). Скан запускается только руками: никаких расписаний и фоновых заданий тут нет намеренно.

Если каталог пуст или инструмент явно есть в системе, но его нет в `nn ls` — сделай `nn init`: он находит установленное по `priors.json` и пишет манифесты в личную директорию пользователя (`$NN_HOME`, по умолчанию `~/.claude/nn/data`). Личные манифесты перекрывают поставляемые с тем же id.

## Команды

```bash
nn init                             # найти установленное и записать манифесты
nn ls [capability]                  # весь парк или один capability
nn why <capability> [--in-type T]   # кто выбран, кто отклонён и почему
nn run <capability> <вход> [-o out] # выполнить; --provider пришпилить, --extra доп. вход
nn recipe ls | run <id> <вход>      # готовые цепочки
nn orchestrate "<задача>" --dir .   # спека → работа в worktree → ревью → вердикт
nn quota                            # окна квот подписок
nn burn add <capability> <вход>     # отложить под простаивающую квоту; burn run --yes выполнить
nn learn                            # сжать исходы запусков в досье провайдеров
nn doctor                           # что сломано в каталоге
nn stats                            # что реально используется
```

## Как читать результат

`nn run` печатает JSON-конверт. Смотри `outcome`, а не только код возврата: `exit 0` успехом не считается.

- `success` — готово, файл в `out`
- `empty` — пустой или подозрительно короткий ответ, повторять тем же промптом бессмысленно
- `quota` / `refused` — не повторять, окно или отказ
- `timeout` / `crash` — движок уже сделал один повтор сам

Коды выхода: `0` ок · `2` нет провайдера · `3` нужен ручной запуск, команда напечатана · `4` провайдер упал · `5` нужен `nn scan` · `6` квота исчерпана · `7` данные битые · `8` тип входа не подходит.

## Правила, которые нельзя обходить

- **Модель не подменяется молча.** Код 6 означает, что у лучшего провайдера кончилось окно; `nn` назвал альтернативу. Передавай `--fallback` только если пользователь согласен на другую модель.
- **Патчи не применяются.** `nn orchestrate` отдаёт `.patch` — предложи пользователю посмотреть и смержить, сам не применяй.
- **Хост с `auto: false` не запускается сам.** Код 3 = команда напечатана; покажи её пользователю, не выполняй молча. Хост `kind: ssh` с `auto: true` работает по-настоящему: вход уезжает туда, выход возвращается, рабочая директория убирается.

## Когда чего-то не хватает

Нет нужного capability или провайдера — не изобретай вызов руками. Сначала `nn init`: возможно, инструмент установлен и его достаточно подключить. Если нет — добавь манифест: один JSON-файл в `$NN_HOME/providers/`, поля описаны в README, готовые шаблоны в `examples/providers/`. Так знание останется в каталоге, а не потеряется в переписке.
