---

Парк нейронок разъезжается. Модели whisper в трёх папках, голосовая модель на MLX, ComfyUI на машине под столом, четыре agent-CLI на подписках, облачный генератор картинок, эмбеддер. Знание «чем это сделать, где лежит, какими флагами звать» остаётся в голове — и каждый новый пайплайн собирается руками заново.

`nn` превращает эту россыпь в каталог с единым контрактом вызова.

```bash
nn ls                          # что у меня вообще есть
nn why transcribe --in-type video   # кого выберет и почему не остальных
nn run transcribe talk.mp4     # → сабы. Мостик до аудио вставится сам
nn run tts script.txt          # → голос
nn recipe run bilingual-subs clip.mp4   # транскрипт → перевод → вжигание, одной командой
```

## Быстрый старт

```bash
git clone https://github.com/Surdeddd/neuropark.git
cd neuropark && ./install.sh
```

Это вся установка. `install.sh` проверяет python, подключает скилл Claude Code, а затем **сам находит твои инструменты** и пишет для них манифесты:

```
инструмент            capability     состояние  модель / причина
--------------------  -------------  ---------  ------------------------------------
whisper-cpp           transcribe     найден     ~/Models/whisper/ggml-large-v3.bin
ffmpeg-audio-clean    audio-clean    найден     ~/Models/rnnoise/sh.rnnn
ffmpeg-compose        compose        найден     -
claude-text           text           найден     -
codex-text            text           найден     -
ollama                text           нет        нет ollama
comfyui               image          нет        эндпоинт не ответил

записано манифестов: 10
```

Чтобы начать, руками настраивать нечего. В рантайме нужен **python 3.11+ и больше ничего** — ни pip install, ни зависимостей.

| шаг | что происходит | как не делать |

TTY хук просто пропускается. Повторный запуск безопасен: существующий симлинк и уже
поставленный хук не перезатираются.

```bash

export NN_STATE=~/my-park-state  # реестр, лог прогонов, досье (по умолчанию ~/.claude/nn)
export NN_LANG=ru              # язык интерфейса
```

## Как это работает

```
    ты ──▶ nn run transcribe video.mp4
                    │
                    ▼
            ┌───────────────┐   capability → провайдер, с причинами
            │   резолвер    │   фильтры: доступен? та ОС? осталась квота?
            └───────┬───────┘   ранжир:  rank → локальный раньше → недавний успех
                    │
              тип не совпал?
                    │  video ≠ audio
                    ▼
            ┌───────────────┐
            │    мостик     │   ffmpeg -vn  →  16k mono wav
            └───────┬───────┘
                    ▼
            ┌───────────────┐   local · ssh (везёт файлы) · manual (печатает)
            │   транспорт   │
            └───────┬───────┘
                    ▼
            ┌───────────────┐   success · empty · timeout · quota · refused · crash
            │     исход     │   exit 0 сам по себе успехом не считается
            └───────┬───────┘
                    ▼
        конверт (JSON) + лог запуска + самозаполняющееся досье
```

Три слоя, и кодом является только средний:

| слой | что там лежит | кто правит |
|---|---|---|
| **данные** | `providers/` `hosts/` `bridges/` `recipes/` `roles.json` `capabilities.json` | ты, текстовым редактором |
| **движок** | resolve · bridge · transport · quota · dossier · orchestrate | 34 модуля, только stdlib |
| **стейт** | реестр, журнал запусков, окна квот, досье, патчи | пишет `nn`, руками не трогают |

В движке **нет списка** инструментов, машин и capability. Всё это данные — поэтому добавление нейронки стоит один файл, а не пул-реквест.

## Добавить нейронку

Один JSON-файл, и имя файла обязано совпадать с `id`:

```json
{
  "id": "whisper-cpp",
  "capability": "transcribe",
  "kind": "model",
  "rank": 10,
  "detect": { "bin": "whisper-cli", "files": ["~/Models/whisper/ggml-large-v3.bin"] },
  "vars":   { "model": "~/Models/whisper/ggml-large-v3.bin" },
  "io":     { "in": ["audio"], "out": "srt" },
  "pre":    "ffmpeg -nostdin -y -i {in} -ar 16000 -ac 1 {tmp}.wav",
  "run":    "whisper-cli -m {model} -f {tmp}.wav -osrt -of {out_base} -l auto",
  "notes":  { "en": "most accurate locally, ~2× slower than turbo",
              "ru": "самый точный локально, примерно вдвое медленнее turbo" }
}
```

Положи в `$NN_HOME/providers/` (по умолчанию `~/.claude/nn/data/providers/`) и сделай `nn scan`. Твои файлы **перекрывают** поставляемые с тем же `id`, поэтому обновление не затрёт то, что ты написал.

<details>
<summary><b>Все поля и девять способов найти инструмент</b></summary>

| поле | смысл |
|---|---|
| `capability` | что умеет. Одна нейронка с двумя умениями = два манифеста |
| `kind` | `model` · `tool` · `agent` |
| `host` | id хоста, по умолчанию `local` |
| `rank` | больше — приоритетнее среди доступных |
| `detect` | как проверить наличие, см. ниже. Все условия соединяются логическим И |
| `requires_key` | env-переменные; их отсутствие даёт статус `needs-key`, а не «нет такой нейронки» |
| `io.in` / `io.out` | классы типов из `capabilities.json`. `out: "same"` сохраняет тип входа |
| `io.out_ext` | когда инструмент пишет контейнер, не совпадающий с расширением по умолчанию |
| `vars` | подстановки для шаблонов; `~` и `$ENV` раскрываются |
| `pre` / `run` / `post` | шаблоны команд, с вариантами под ОС: `{"darwin": "…", "linux": "…"}` |
| `timeout_s` | по умолчанию 900 |
| `window_h`, `soft_cap_calls` | длина квотного окна и мягкий лимит вызовов |
| `quota_patterns` | регулярки по stderr, означающие исчерпание окна |
| `vendor` | для оркестрации: ревью обязано идти другим вендором |
| `notes` | **обязательны**, двуязычные `{en, ru}`: скорость, качество, известные грабли |

Стратегии детекта: `bin` · `files` · `glob` · `env` · `http` · `python` · `npm` · `docker` · `brew`.

Переменные шаблонов: `{in}` `{out}` `{out_base}` `{tmp}` `{dir}` `{prompt_file}` `{extra0}` `{host.paths.ключ}` плюс всё из `vars`. Неизвестная переменная — ошибка валидации, а не тихая пустая строка.

Готовые шаблоны лежат в [`examples/`](examples/): скрипт со своим интерпретатором, инструмент на другой машине, ssh-хост с секретом по ссылке.

</details>

<details>
<summary><b>Добавить машину</b></summary>

```json
{ "id": "gpu-box", "kind": "ssh", "addr": "gpu-box", "auto": true,
  "probe": "ssh -o ConnectTimeout=3 -o BatchMode=yes gpu-box true",
  "paths": { "models": "/data/models", "tmp": "/var/tmp" },
  "env": { "PATH": "/usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin" } }
```

`kind`: `local` · `ssh` · `http` · `manual`. **`auto: false` означает, что `nn` печатает готовую команду вместо запуска** — удобно для машины, которую хочется вести руками, и единственный режим, который есть у `http`.

**Удалённый прогон при `auto: true`** отправляет вход в `paths.tmp` (по умолчанию `/tmp`), выполняет команду в директории прогона, забирает выход обратно и убирает эту директорию — чем бы прогон ни кончился. Файлы едут тем же ssh-каналом, которым запускается команда, поэтому ставить на машину сверх `ssh` ничего не нужно. Спящий или недоступный хост становится записанным прогоном с исходом `crash`, а не трейсбеком.

> **Задай `env.PATH`.** У неинтерактивного ssh-шелла PATH урезан: он не видит ни `/opt/homebrew/bin`, ни `/usr/local/bin`. Без этого установленный инструмент всё равно ответит `command not found` — досье потом это и подскажет, но узнаешь ты ценой одного прогона.

Порт, файл ключа и jump-хост место имеют в `~/.ssh/config` (тогда `addr` — просто алиас); `"ssh_options": ["-p", "2222"]` оставлен для разового случая. `BatchMode` включён всегда, поэтому nn не зависает на приглашении пароля.

Секреты только ссылкой: `"KEY": "@file:~/.config/secrets/k"`. Читаются в момент запуска, в git не попадают — а в удалённом прогоне доходят до команды через окружение шелла: не через `argv` (его видно в `ps` на той стороне) и не файлом на диске удалённой машины.

</details>

## Цепочки

Рецепт — это данные. Выход шага N становится входом N+1, а при несовпадении типов мостик вставляется сам:

```json
{ "id": "bilingual-subs",
  "steps": [
    { "capability": "transcribe" },
    { "capability": "translate", "vars": { "lang": "ru" } },
    { "capability": "subtitle-burn", "in": "{input}", "extra_in": ["{step1.out}"] }
  ] }
```

```bash
nn recipe run bilingual-subs clip.mp4
```

`{input}` — исходный вход рецепта, `{stepK.out}` — выход K-го шага. Ссылки вперёд отклоняются на валидации.

## Оркестрация

Для работы, которая заслуживает больше одной модели:

```bash
nn adapt                                   # разложить текстовые CLI по ролям, один раз
nn orchestrate "починить парсер" --dir .    # спека → работа → кросс-ревью → вердикт
nn orchestrate "…" --fanout 3               # три попытки, каждая в своём worktree
```

Две гарантии, обе закрыты тестами:

- **Ревью идёт другим вендором**, чем автор патча. Модель не проверяет саму себя.
- **Патч не применяется никогда.** Работа идёт в изолированном `git worktree` от HEAD, наружу отдаётся `.patch`. Мерж — твоё решение. Репозиторий в середине rebase отклоняется до создания worktree.

## Квоты и досье

И то, и другое заполняется само из журнала запусков — поддерживать руками нечего.

```bash
nn quota          # окна: сожжено, что простаивает, когда закроется
nn burn add image prompt.txt && nn burn run --yes   # потратить окно, которое иначе истечёт
nn learn          # сжать неудачи в досье провайдеров
```

Досье — это то, что каталог узнал болью, собранное без всякого LLM:

```
## observed
- «modulenotfounderror: no module named mlx_audio» × 3, последний раз 2026-08-12T10:00

## instructions
- у провайдера свой интерпретатор: проверь vars.py, системный python не годится
```

Эта инструкция с тех пор подмешивается в промпт провайдера. Отключается на вызов флагом `--no-dossier`.

## Два правила, которые движок не нарушает

> **Никаких молчаливых подмен модели.** Если у лучшего провайдера исчерпано окно, `nn` падает с кодом 6, называет живую альтернативу и ждёт `--fallback`. Подмена происходит только когда ты её попросил.

> **Ничего не применяется само.** Патчи не мержатся, хосты с `auto: false` печатают команду, скан только читает, `burn` без `--yes` только предлагает.

## Язык

Весь интерфейс говорит по-английски и по-русски. `NN_LANG=en` или `NN_LANG=ru`; без переменной язык берётся из `LC_ALL`/`LANG`, иначе английский. Переключаются справка команд, сообщения, заголовки таблиц и заметки об инструментах.

## Коды выхода

Сделаны для скриптов и агентов, а не только для человека:

| код | значение |
|---|---|
| `0` | успех |
| `2` | нет доступного провайдера под capability |
| `3` | требуется ручной запуск — команда напечатана |
| `4` | провайдер упал |
| `5` | реестра нет либо он старше 30 дней → сделай `nn scan` |
| `6` | окно квоты исчерпано |
| `7` | невалидный манифест, шаблон или рецепт |
| `8` | беда со входом: файла нет, тип не поддержан и мостика нет, либо не хватает обязательного `--extra` |

Классы исхода в каждом конверте: `success` `empty` `timeout` `quota` `refused` `crash`. Пустой файл или ответ вида *«Ready to work. What's the task?»* классифицируется как `empty`, а не успех.

## Свежесть каталога

Скан запускаешь ты: `nn scan`. Расписаний, демонов и уведомлений тут **намеренно нет** — меньше инфраструктуры, меньше поводов ей сгнить. Скан сам докладывает, что изменилось:

```
изменения с прошлого скана
появилось:
  ollama — новая нейронка, статус ok
исчезло:
  kimi-text — манифест исчез из каталога
```

## Почему это не умрёт

`nn` заменил две мои предыдущие попытки, которые умерли: за месяц они собрали 4 вызова, а досье моделей так и остались пустыми навсегда. Разбор причин и определил этот дизайн:

| что их убило | что изменилось |
|---|---|
| требовали ручного посева конфигов и досье | квоты и досье считаются сами из журнала запусков |
| несли сложность раньше, чем она окупалась | шесть фаз, каждая проверена на живом железе до следующей |
| их не звали — не было явных триггеров | описание скилла перечисляет, когда за ним тянуться, на двух языках |
| нельзя было увидеть, что не используется | `nn stats` — фича с нулём вызовов за месяц выпиливается, а не доделывается |

## Разработка

```bash
make help         # все цели
make check        # ruff + ruff format + mypy --strict + 382 юнита, без сети, ~10с
make smoke-fast   # живые прогоны офлайн: скан, транскрипт, мостик, доктор (~30с)
make smoke        # плюс TTS с холодным старом модели (до 15 минут)
make hooks        # гит-хук pre-commit: те же проверки до того, как что-то попадёт в историю
```

CI гоняет `make check` на ubuntu и macOS для python 3.11, 3.12 и 3.13, а затем делает
**холодный старт на пустой машине** — `init` → `scan` → `ls` → `doctor` с чистым `NN_HOME`,
где почти ни одного инструмента нет, — и проверяет, что отвечают оба языка.

Правила, которые держатся: только stdlib в рантайме · ни одного `type: ignore` во всём `src` · тесты не ходят в сеть и не тратят подписки · весь текст для человека двуязычный через `nn.i18n.bi`.

Чтобы добавить инструмент, код писать не нужно — см. [CONTRIBUTING.md](CONTRIBUTING.md). Заметки к релизам: [CHANGELOG.md](CHANGELOG.md).

Не реализовано, и об этом честно сообщается вместо тихого падения: транспорт `http` (такие хосты печатают команду), провайдеры с `adapter` для инструментов с очередью, рецепты с несколькими входами.
